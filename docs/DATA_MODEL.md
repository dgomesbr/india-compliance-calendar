# Data model

All calendar data lives in `data/` as YAML and is validated by `npm run validate`
and the test suite on every change. Prose is ASCII only: straight quotes, " - "
instead of dashes, "Rs" instead of the rupee sign.

```
data/
  meta.yaml          confirmedThrough date and data version
  rules/*.yaml       obligations, one file per law area
  holidays/*.yaml    official holiday lists
  events.yaml        event types for the planner (AGM, allotment, ...)
  feeds.yaml         regulator feeds collected into updates.json
  sources.yaml       catalogue of open datasets and official sources
  updates.json       generated by scripts/fetch-feeds.ts
```

## Rules

A rule is a recurring or event-driven obligation, never a single dated row. The
site expands rules into dated occurrences for any window up to 24 months ahead.

| Field | Required | Meaning |
|---|---|---|
| `id` | yes | kebab-case, unique and stable; used in URLs, feed UIDs and filed records |
| `code` | yes | short catalog code shown as the obligation's number, e.g. `GSTR-3B` |
| `title` | yes | up to 72 characters |
| `form` | no | official form, return or challan name |
| `category` | yes | `income-tax`, `gst`, `mca`, `sebi`, `rbi-fema`, `labour`, `state`, `trade`, `other` |
| `authority` | yes | who administers it |
| `summary` | yes | what is filed or paid, one or two sentences |
| `applicability` | yes | who must comply, with thresholds |
| `audience` | yes | one or more of `company`, `listed`, `llp`, `firm`, `individual`, `trust`, `employer`, `gst`, `tds`, `foreign`, `audit`, `importer-exporter` |
| `tags` | no | applicability refinements: `gst-monthly`, `gst-qrmp`, `gst-composition`, `gst-regular`, `opc-small`, `not-opc-small`, `opc`, `not-opc`, `public-company`, `unlisted`, `unlisted-public`, `transfer-pricing`, `non-audit` |
| `frequency` | yes | `monthly`, `quarterly`, `half-yearly`, `annual`, `every-n-years`, `event`, `one-time` |
| `schedule` | unless event | see below |
| `trigger` | for events | e.g. "Within 30 days of allotment" |
| `law` | yes | sections and rules |
| `penalty` | no | prose: late fee, interest, penalty with sections |
| `exposure` | no | structured penalty, see below |
| `states` | no | ISO 3166-2:IN codes without `IN-` for state rules (`MH`, `KA`, `TS`...) |
| `effective` | no | `{from, to}`: applies to periods starting in this window |
| `overrides` | no | notified extensions, see below |
| `sources` | yes | `{title, url, kind}`; primary government sources first |
| `verified` | yes | date the rule was checked |
| `confidence` | yes | `high` (primary source), `medium` (secondary source), `low` (unconfirmed, explained in notes) |
| `notes` | no | caveats and recent changes |

### Schedules

Periodic kinds place the due date relative to the last month of the period:
`day` of (period's last month + `monthOffset`). `day` may be `last`; days past
the month length clamp to its last day. Alternatively `daysAfter` (calendar days
after the period end) or `workingDaysAfter` (Monday to Friday, skipping central
gazetted holidays).

| kind | periods | example |
|---|---|---|
| `monthly` | calendar months | GSTR-3B: `{kind: monthly, day: 20, monthOffset: 1}` |
| `quarterly` | `basis: fy` (default) Q1 Apr-Jun ... Q4 Jan-Mar, or `basis: calendar` | TDS statements: `{kind: quarterly, day: 31, monthOffset: 1, except: {Q4: {day: 31, monthOffset: 2}}}` |
| `half-yearly` | FY halves (Apr-Sep, Oct-Mar) or calendar halves | MSME-1: `{kind: half-yearly, day: last, monthOffset: 1}` |
| `annual` | financial year or calendar year | GSTR-9: `{kind: annual, day: 31, monthOffset: 9}` |
| `every-n-years` | one year in `everyYears`, counted from `anchor` | `{kind: every-n-years, everyYears: 3, anchor: FY2027-28, day: 30, monthOffset: 3}` |
| `fixed` | explicit `dates: [{due, period}]` | true one-offs only |

`except` overrides placement for some periods (keys `"1"`..`"12"`, `Q1`..`Q4`,
`H1`/`H2`); `skip` drops periods. Advance tax is
`{kind: quarterly, day: 15, monthOffset: 0}`.

`after: {months, days}` is the exact placement for "within N months (and N days)
of the period end": the same date N months on, clamped to the month's length
(31 March plus six months is 30 September; 30 June plus six is 30 December), then
the days. When present it wins over the other fields; `day` and `monthOffset`
stay beside it with the April-March answer for older readers of the data.

### The entity's financial year

`entityYear: true` marks a schedule whose periods follow the entity's own
financial year rather than the statutory April-March one: company law (the AGM
and its filings, AOC-4 for an OPC, cost audit), LLP returns, SEBI results and
annual filings, and the FEMA annual activity certificate. A company that is a
holding company, subsidiary or associate of a company incorporated outside India,
and must follow a different year for consolidation there, may have it approved by
the Tribunal (proviso to section 2(41), Companies Act 2013); an LLP in that
position, by the Central Government (section 2(1)(l), LLP Act 2008). The team sets the first month
in its profile (`profile.fyStart`, 1-12, default 4). Income tax, TDS and GST
never carry the flag.

With April as the first month nothing changes: period keys stay `FY2026-27`,
`FY2026-27-Q1`, `FY2026-27-H1`, so filed records and overrides keep matching.
Any other start uses keys named by the year's end, `FYE2026-12` (the year ending
December 2026) and `FYE2026-12-Q1`, labelled "FY 2026 (Jan-Dec)" or "FY 2026-27
(Jul-Jun)". Quarters and halves run from the first month, so `except: {Q4: ...}`
always means the year's last quarter. Overrides are recorded for April-March
years and apply only there.

### Chains

`follows` places a rule from another rule's occurrence for the same period
instead of from the period end:

```yaml
schedule:
  kind: annual
  basis: fy
  entityYear: true
  day: 30            # the April-March answer, kept for older readers
  monthOffset: 7
  follows:
    rule: mca-agm-annual
    within: { days: 30 }   # months and/or days; negative for "before"
    from: done             # done (default) or due
```

| Field | Meaning |
|---|---|
| `rule` | the earlier rule; it must share the basis and `entityYear` |
| `slot` | for an annual rule that follows one quarter or half of a more frequent rule, e.g. `Q4` |
| `within` | `{months, days}` from the earlier occurrence; `monthEnd: true` takes a month's last day to the target month's last day (CBDT counts one month before 30 November as 31 October) |
| `from` | `done`: the date the team recorded for the earlier occurrence (filed, or held for a meeting), else its due date; `due`: always its due date, including any extension |
| `earlier` | "whichever is earlier": the rule keeps its own date and a recorded earlier step can only bring it forward (the GST credit cut-off and the GSTR-9 filing date) |

A notified override on the rule itself still wins. Chains are validated: the
earlier rule must exist, chains may not loop, and the test suite checks that
every chain reproduces the rule's own April-March dates. Unrecorded, a `done`
chain counts from the earlier step's due date as extended (the AGM that should
have been held); a `due` chain counts from its statutory date, because linked
dates are extended separately (each extension is recorded on its own rule).
`recordAs: held` marks a meeting, so the site says "Mark held" and "Held on" for
it, and `sameEventAs` names the rule a second deadline for the same meeting keeps
its record under (the top 100 listed entities' AGM is the Companies Act AGM).

### Overrides

```yaml
overrides:
  - period: FY2025-26          # "2026-08", "FY2026-27-Q1", "FY2026-27-H1", "FY2025-26", "CY2026"
    due: 2026-10-31
    originalDue: 2026-09-30
    reason: Extended by CBDT Circular No. X/2026 dated DD-MM-2026
    source: { title: CBDT Circular X/2026, url: https://... }
```

An occurrence moved by an override shows the new date, keeps the statutory one in
`originalDue`, and is never flagged projected.

### Exposure

```yaml
exposure:
  lateFeePerDay: 200        # Rs per day of delay
  lateFeeCap: null          # cap on that fee
  fixedPenalty: 10000       # flat penalty on default (statutory minimum of a range)
  maxPenalty: 100000        # statutory maximum on the entity
  interestPctPerMonth: 1.5  # or interestPctPerAnnum
  percentOfTurnover: null
  other: [Expense disallowance]
  basis: Section 234E fee; 271H penalty Rs 10,000 to 1,00,000
```

The site sorts by the fixed cost of a 30-day delay: late fee (capped) plus the
flat penalty, capped at the maximum. Interest depends on the tax amount, so it is
shown, not summed.

## Occurrences

`expandRule(rule, from, to, opts)` in `src/lib/schedule.ts` returns occurrences
with a stable `key` (`<ruleId>@<periodKey>`), `due`, `periodKey`, `periodLabel`,
period start and end, `originalDue` and `extended` when moved, `projected` when
the due date is past `confirmedThrough` in `data/meta.yaml`, and `chain` (the
earlier occurrence, the date the clock ran from and whether that date was
recorded or its due date) for a rule that follows another. `opts` carries every
rule by id (so chains resolve), the entity's first month and the recorded dates;
`expandOptions(bundle, {fyStart, filed})` in `src/lib/view.ts` builds it, and
`lineage()` walks a chain both ways for the detail panel and entry pages.

## Holidays

```yaml
lists:
  - id: central-gazetted-2026
    title: Central Government gazetted holidays 2026 (Delhi / New Delhi)
    kind: gazetted          # gazetted | restricted | bank | exchange-trading | exchange-settlement
    scope: IN               # IN, a state code, NSE or BSE
    year: 2026
    authority: Department of Personnel and Training
    source: { title: ..., url: ... }
    verified: 2026-10-14
    confidence: high
    holidays:
      - { date: 2026-01-26, name: Republic Day }
```

## Planner events

```yaml
events:
  - id: agm-held
    title: Annual general meeting held
    description: Filings that run from the date of the AGM.
    category: mca
    steps:
      - ruleId: mca-aoc4          # optional link to a rule
        code: AOC-4
        title: Financial statements
        within: { days: 30 }      # or { months: 1 }; negative days for "before"
        law: "Section 137, Companies Act 2013"
```
